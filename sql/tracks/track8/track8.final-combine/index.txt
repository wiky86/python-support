3:T8b0,## 지금까지 배운 모든 것을 하나로

SQL 과정의 마지막 토픽입니다. 조회(SELECT/WHERE), 정렬(ORDER BY), 집계(GROUP BY), 조인(JOIN), 서브쿼리, 윈도우 함수, CTE를 **하나의 실전 쿼리로** 조립합니다. 실무의 분석 쿼리는 이렇게 여러 기술을 결합해 만들어집니다.

## 예제: 부서별 급여 1위 직원 (이름·부서명 포함)

요구사항: '각 부서에서 급여가 가장 높은 직원의 이름, 부서 이름, 급여를 보여줘.'

```sql
WITH ranked AS (
  SELECT e.emp_name, e.salary, d.dept_name,
         ROW_NUMBER() OVER (PARTITION BY e.dept_id ORDER BY e.salary DESC) AS rn
  FROM employees e
  JOIN departments d ON e.dept_id = d.dept_id
)
SELECT emp_name, dept_name, salary
FROM ranked
WHERE rn = 1
ORDER BY salary DESC;
```

단계별로 읽어봅시다.
1. **CTE(ranked)** 안에서 employees와 departments를 **조인**하고, 부서별로 급여 순위(**윈도우 함수 ROW_NUMBER + PARTITION BY**)를 매깁니다.
2. 바깥 쿼리에서 **rn = 1**(각 부서 1위)만 걸러내고, 급여 높은 순으로 **정렬**합니다.

결과: 김철수(영업·6000), 박민수(개발·5000), 임재현(마케팅·4800), 강다연(인사·4000).

## 왜 이렇게 조립하나

- 조인 없이는 부서 '이름'을 못 봅니다 → JOIN.
- 부서별 1위는 GROUP BY로 못 뽑습니다(개별 행이 사라짐) → 윈도우 함수.
- 윈도우 결과(순위)는 WHERE에서 바로 못 씁니다 → CTE로 감싼 뒤 걸러냄.

각 기술이 '한계'를 서로 보완하며 조립됩니다. 이것이 SQL 실무의 핵심 사고방식입니다.

## 작성 순서 팁

복잡한 쿼리는 한 번에 쓰지 말고 단계적으로 만드세요.
1. 먼저 필요한 테이블을 조인해 기본 데이터를 만든다.
2. 필요한 계산(순위·집계)을 추가한다.
3. CTE로 감싸 정리하고, 바깥에서 조건·정렬을 건다.
